1. Ringkasan

Aplikasi terdiri dari situs publik (Bahasa Indonesia) dan panel admin di /admin dalam satu project Next.js. Seluruh konten — profil perusahaan, 4 bidang usaha, galeri foto, slider beranda, armada rental, dan akun admin — dikelola dari panel admin dan disimpan di database MySQL-compatible; file foto disimpan di Cloudinary.

Situs publik

Beranda, Tentang Kami, Bidang Usaha, Detail Bidang Usaha + galeri lightbox, Armada (daftar & detail), Kontak + formulir.

Panel admin

Dashboard, Bidang Usaha, Galeri Foto, Slider Beranda, Armada Rental, Profil Perusahaan, Pesan Masuk, Pengguna Admin.

Rendering

Halaman publik di-prerender statis (ISR, revalidate 1 jam) dan di-revalidate on-demand setiap kali admin menyimpan perubahan.

2. Arsitektur aplikasi

Strategi rendering & revalidation

  • Halaman publik (src/app/(site)) di-prerender saat build. Setiap halaman mengekspor revalidate = 3600 sebagai pengaman, dan halaman detail memakai generateStaticParams + dynamicParams = true sehingga bidang usaha/armada baru otomatis dibuat on-demand.
  • On-demand revalidation: setiap Server Action admin yang mengubah konten memanggil revalidatePublic() → revalidatePath("/", "layout"). Kunjungan berikutnya menampilkan konten terbaru (diuji otomatis — lihat laporan pengujian).
  • Panel admin dirender dinamis per request (membaca sesi/cookie).
  • Model caching yang dipakai adalah model klasik (tanpa cacheComponents) agar kompatibel penuh dengan runtime Netlify.

8. Server Actions & API

Semua mutasi memakai Server Actions (src/server/actions/*.ts). Setiap action admin: (1) memanggil requireAdmin() (cek sesi ulang, tidak hanya mengandalkan proxy), (2) memvalidasi input dengan Zod, (3) menulis ke database, (4) membersihkan file Cloudinary yang tidak terpakai, (5) memanggil revalidation. Nilai kembali bertipe ActionResult = {ok:true,message?,data?} | {ok:false,error,fieldErrors?}.

9. Keamanan

Autentikasi

Auth.js Credentials, password bcrypt (cost 12), sesi JWT dalam cookie httpOnly/secure (8 jam). Perbandingan hash dilakukan walau email tidak terdaftar (waktu respons seragam).

Otorisasi berlapis

proxy.ts mengunci /admin/* dan /api/admin/*; setiap halaman & Server Action admin memanggil requireAdmin() lagi.

Brute-force

Maks 5 login gagal per menit per IP dan per email (tabel rate_limits, berlaku lintas instance serverless).

Validasi server

Semua input divalidasi Zod di server; HTML rich text disanitasi (sanitize-html, whitelist tag); ID dan urutan divalidasi.

Anti-spam formulir

Honeypot field tersembunyi, time-trap (< 3 detik = bot), rate limit 3 pesan/10 menit/IP; IP disimpan sebagai hash SHA-256 ber-salt.

Upload

Signed upload (signature dibuat server, hanya untuk admin, folder whitelist, allowed_formats), lalu verifikasi ulang ke Cloudinary API (format & ukuran) — aset tidak valid otomatis dihapus.

Header keamanan

HSTS, X-Frame-Options SAMEORIGIN, X-Content-Type-Options nosniff, Referrer-Policy, Permissions-Policy; header X-Powered-By dimatikan. Admin & API di-noindex/Disallow.

Secret

Hanya melalui environment variables; tidak ada secret di kode/Git. Server Actions Next.js memiliki proteksi CSRF bawaan (cek Origin).

10. Upload & Cloudinary

  1. Admin memilih/seret foto (maks 20, JPG/PNG/WebP, ≤ 5 MB) — divalidasi di browser.
  2. Foto besar dikompres ringan di browser (sisi terpanjang ≤ 2400 px) untuk menghemat kuota.
  3. Browser meminta signature ke /api/admin/cloudinary/sign, lalu meng-upload langsung ke Cloudinary (3 file paralel, progress per file) — tidak melewati batas ukuran request serverless Netlify.
  4. Hasil (public_id, URL, dimensi) dikirim ke Server Action yang memverifikasi tiap aset via Cloudinary Admin API, lalu menyimpan ke database dengan urutan berikutnya.
  5. Tampilan memakai transformasi URL: f_auto,q_auto,c_limit,w_… → WebP/AVIF otomatis; thumbnail admin 400 px, lightbox 1600 px, next/image dengan loader Cloudinary (srcset responsif, lazy-load).
  6. Saat foto/slider/sampul/logo dihapus atau diganti, file di Cloudinary ikut dihapus (uploader.destroy/delete_resources, invalidate CDN).

Struktur folder: arsindo/gallery/{slug-bidang}, arsindo/fleet/{slug-armada}, arsindo/sliders, arsindo/covers, arsindo/brand.

Jika slug bidang usaha/armada diubah setelah ada foto, foto lama tetap berfungsi (URL tersimpan di database); upload baru masuk ke folder slug baru.

11. SEO, performa, aksesibilitas

  • Metadata API per halaman (title template, description, canonical, Open Graph & gambar OG dinamis 1200×630), sitemap.xml (termasuk detail bidang usaha & armada aktif), robots.txt, JSON-LD LocalBusiness, lang="id", alt text foto dari caption.
  • Performa: halaman statis ISR; font self-hosted + preload + fallback metrics (CLS 0); gambar via Cloudinary (format/ukuran otomatis); Google Maps dimuat hanya saat terlihat; prefetch link konten dimatikan agar tidak membebani main thread; animasi berbasis CSS + satu IntersectionObserver global; dekorasi memakai radial-gradient (bukan filter blur).
  • Aksesibilitas: skip link, landmark & aria-label navigasi, fokus terlihat, kontras warna memenuhi WCAG AA, dukungan prefers-reduced-motion, drag-and-drop admin dapat dioperasikan dengan keyboard (Space → panah → Space).
  • Responsif: diuji otomatis tanpa scroll horizontal pada 360, 768, 1024, 1920 px.

13. Prosedur deployment (Netlify + TiDB + Cloudinary)

A. Database — TiDB Cloud Serverless

  1. Daftar di tidbcloud.com → Create Cluster (Serverless, region Singapore ap-southeast-1).
  2. Connect → pilih “General”, buat password → salin host, port 4000, user (format xxxx.root).
  3. Buat database: CREATE DATABASE arsindo; (SQL Editor).
  4. DATABASE_URL=mysql://xxxx.root:PASSWORD@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/arsindo?sslaccept=strict

B. Cloudinary

  1. Daftar akun gratis → Settings → API Keys: catat Cloud name, API Key, API Secret.
  2. (Opsional) Settings → Security: aktifkan “Strict transformations” tidak diperlukan; biarkan default.

C. GitHub & Netlify

  1. Push repo ke GitHub (branch main).
  2. Netlify → Add new site → Import an existing project → pilih repo. Build settings otomatis dari netlify.toml (npx prisma migrate deploy && npm run build, Node 22).
  3. Isi environment variables (bagian 7) untuk scope Builds dan Functions. AUTH_URL & NEXT_PUBLIC_SITE_URL = URL final.
  4. Deploy site. Migration otomatis diterapkan saat build.
  5. Seeder (sekali): di komputer lokal set DATABASE_URL production sementara lalu npm run db:seed. Login ke /admin, ganti password, lengkapi NIB/NPWP, logo, slider, dan foto.

D. Domain & HTTPS

  1. Netlify → Domain management → Add a domain (mis. arsindoniaga.co.id).
  2. Di DNS registrar: A @ → 75.2.60.5 dan CNAME www → <nama-site>.netlify.app (atau gunakan Netlify DNS).
  3. Tunggu propagasi, Netlify menerbitkan sertifikat Let's Encrypt otomatis → aktifkan “Force HTTPS”.
  4. Perbarui AUTH_URL & NEXT_PUBLIC_SITE_URL ke domain final → Trigger deploy.
  5. Daftarkan https://domain/sitemap.xml di Google Search Console.

E. Checklist verifikasi pasca-deploy

  • ☐ https://domain terbuka dengan gembok HTTPS, http → https redirect.
  • ☐ Login admin, upload 10 foto ke “Rental Mobil”, foto tampil di /bidang-usaha/rental-mobil.
  • ☐ Ubah urutan, nonaktifkan, dan hapus foto → website ikut berubah.
  • ☐ Kirim formulir kontak → muncul di Pesan Masuk.
  • ☐ PageSpeed Insights mobile ≥ 80 untuk Beranda.

15. Panduan operasional admin

Menambah foto dokumentasi

Galeri Foto → pilih bidang usaha → seret foto ke kotak upload (maks 20 sekaligus) → tunggu progress selesai → isi caption → klik Simpan pada caption. Seret ikon ⋮⋮ untuk mengubah urutan; switch untuk tampil/sembunyi.

Mengganti banner beranda

Slider Beranda → Tambah Slider → unggah gambar landscape ≥ 1920×1080 → isi judul, subjudul, teks & link tombol → Simpan. Jika semua slider dinonaktifkan, beranda memakai hero default.

Menambah armada

Armada Rental → Tambah Armada → isi data → Simpan → di halaman edit, unggah foto unit. Aktifkan switch agar tampil di /armada.

Mengubah profil & kontak

Profil Perusahaan → ubah teks, NIB/NPWP, nomor WhatsApp (08xx atau 628xx), URL embed Google Maps (Bagikan → Sematkan peta → salin src) → Simpan Profil.

Pesan Masuk → klik pesan (otomatis ditandai dibaca) → balas lewat tombol email/WA. Jumlah pesan baru tampil di menu & dashboard.

Akun admin

Pengguna Admin → tambah akun staf (password ≥ 8 karakter, huruf + angka), reset password, atau ganti password sendiri.

16. Catatan & keputusan teknis

  • Penambahan terhadap PRD: tabel vehicles & vehicle_photos (armada terpisah dari galeri, sesuai jawaban pertanyaan terbuka PRD), rate_limits (rate limit serverless), kolom services & wa_message pada bidang usaha, ip_hash pada pesan. Menu publik ditambah “Armada”.
  • Prisma 7 dipakai dengan driver adapter MariaDB (kompatibel MySQL 8 & TiDB) — tidak ada binary query engine sehingga ringan di serverless. Konfigurasi koneksi ada di prisma.config.ts dan src/lib/prisma-factory.ts.
  • Migration awal ditulis dalam format SQL Prisma dan telah diterapkan/diuji pada MariaDB 10.11 di lingkungan pengujian. Jalankan npx prisma migrate dev sekali di lokal untuk memastikan schema “in sync” sebelum deploy.
  • Komponen UI bergaya shadcn/ui ditulis langsung di src/components/ui (berbasis Radix UI) sehingga tidak bergantung pada CLI registry.
  • Konten awal (deskripsi bidang usaha, profil, visi, misi, nilai, komitmen) adalah draf yang disusun dari PRD — mohon diverifikasi terhadap company profile PDF resmi dan disesuaikan melalui panel admin. NIB & NPWP sengaja kosong sampai diisi admin.
  • Tidak termasuk v1 (sesuai PRD): booking/pembayaran online, katalog produk berharga/stok, multi-bahasa, blog, akun pengunjung.
